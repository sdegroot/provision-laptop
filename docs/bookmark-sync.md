# Bookmark Sync (Brave)

Brave bookmarks are tracked in this repo as canonical JSON files under `state/bookmarks/`, one file per profile listed in `state/brave-profiles.conf`. Pull captures the live state into the repo; push restores the repo state into a profile; the dotfiles module seeds bookmarks into a fresh profile on first apply.

Safari is **not** synced — see [Why no Safari?](#why-no-safari) below.

## Layout

```
state/bookmarks/
  brave-Utrecht.json
  brave-Epistola.json
  brave-Sittard-Geleen.json
  brave-Fluxzero.json
  brave-Personal.json
  brave-Company.json
```

One file per profile means small, focused diffs — adding a bookmark to *Personal* doesn't touch *Company*'s file.

## Commands

```bash
bin/sync-bookmarks pull     # live → repo
bin/sync-bookmarks push     # repo → live (Brave must be quit)
bin/sync-bookmarks --help
```

| Command | Direction | Destructive? | Notes |
|---|---|---|---|
| `pull` | live → repo | No | Safe to run while Brave is open. Strips noise (see below). Run when you want to capture current state. |
| `push` | repo → live | **Yes — overwrites the live `Bookmarks` file** | Refuses to run if Brave is running. Removes Chromium's `Bookmarks.bak` so the push isn't undone on next launch. |

After `pull`, run `git diff state/bookmarks/` to review changes before committing.

## Strip rules

The live Chromium `Bookmarks` file contains fields that change on every browse, even without bookmark edits — e.g. timestamps and per-visit metadata. `pull` writes a canonical form with these stripped, so committed diffs only show real changes (additions, removals, renames, reorderings).

**Stripped at top level:**
- `checksum` — derived
- `sync_metadata` — Chromium sync state

**Stripped per node:**
- `id` — local-only, regenerated by Brave on load
- `date_last_used` — updates on every visit
- `meta_info.last_visited_desktop`
- `meta_info.stars.cluster_uuid`

**Preserved:**
- `guid` — stable identity, survives renames
- `name`, `url`, `type`, `children`
- `date_added` — immutable per bookmark
- `date_modified` — useful for folder-level changes
- Any other `meta_info` fields not listed above

If Brave changes its file format and a new noisy field appears, add it to `NOISY_TOP`/`NOISY_NODE`/`NOISY_META` in `bin/sync-bookmarks`.

## Apply-time seeding

The `dotfiles` module's `apply.sh` seeds bookmarks into a Brave profile **only if** the live `Bookmarks` file is missing OR has empty roots (Brave creates an empty file on first launch). Existing bookmarks are never touched by `bin/apply` — re-runs are idempotent.

```
state/bookmarks/brave-Personal.json     →     ~/Library/Application Support/BraveSoftware/Brave-Browser/Personal/Bookmarks
                                              (only if no bookmarks there yet)
```

So a fresh Mac running `bin/apply` will get the committed bookmark sets pre-populated, and from there native Brave Sync (if you have it on) takes over.

## Workflow

### Day-to-day

1. Edit bookmarks normally in Brave.
2. When you want to capture them: `bin/sync-bookmarks pull`
3. `git diff state/bookmarks/` to review.
4. Commit if happy.

### Restoring a profile (rare)

1. Quit Brave (⌘Q).
2. `bin/sync-bookmarks push`
3. Launch Brave — restored bookmarks appear in the profile.

### Fresh Mac

1. `bin/apply` runs — `dotfiles` seeds bookmarks into newly-created Brave profiles.
2. Sign in to Brave Sync if you use it; cross-device state takes over from there.

## Cross-device drift

If you `pull` from Mac A and Mac B independently, last-pull-wins. The repo only knows about whichever machine ran `pull` most recently.

Recommendation: keep **Brave Sync** on (Settings → Sync), so live state stays consistent across your devices. The repo then captures whichever device you happened to run `pull` from.

## Why no Safari?

Safari's `~/Library/Safari/Bookmarks.plist` is:

1. **Binary plist** — git diffs are unreadable. Could be converted to XML via `plutil`, but the format is messier than Chromium's JSON.
2. **Sandbox-protected** — reading or writing the file requires Full Disk Access for the terminal. One-time grant, but bootstrap can't automate it.
3. **Already synced via iCloud** — if you have iCloud Bookmarks on, cross-device sync is already handled.

Net: not worth the friction. iCloud handles Safari bookmarks well enough.
